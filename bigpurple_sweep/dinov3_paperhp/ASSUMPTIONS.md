# Goal-1 DINOv3 paperhp sweep — assumptions and provenance (2026-07-30)

The sweep runs the **paper's per-cell (benchmark × backbone) HP winners** from
`best_hyperparameters.csv` (qz-compcont-learning, branch `REBUT/min`) across seeds
{1993, 42, 7, 2024, 31337} on DINOv3-B/L/H × the 6 standard EASE benchmarks
(18 cells, 90 runs). Configs generated by `gen_paperhp.py`; per-config provenance
(qz sweep name, qz run_id, exact overrides) in `provenance.json`.

## Assumptions, in decreasing order of importance

1. **cifar-100 × dinov3_vitb16 HPs are hash-recovered, not recorded.** The CSV row
   and the winner's result JSON (`dinov3_min_focused/cifar_100/af00f92dfdf2.json`)
   both lack the config; the sweep manifest was overwritten by a later 1-run sweep.
   qz's `make_run_id()` is `sha256(json.dumps(sorted(cfg)))[:12]`, so the run_id
   was brute-forced over the `dinov3_min_focused` grid. It matches only under the
   **pre-6bd7f98 grid** (`min_batch_size=512, min_init_batch_size=512,
   min_buffer_batch=2000`, later reduced to 256/256/1000 to avoid OOM):
   → **lr=5e-05, gamma=100, hidden_dim=96, batch=512/512, buffer_batch=2000.**
   Validation: the same procedure exactly reproduces the run_ids of two winners
   whose configs ARE recorded (cub-200 `6eb614af33dd`, imagenet-r `c119cc4410e1`).
   Implication: this winner was found at batch 512 — a grid point the later
   (committed) YAML can no longer produce.

2. **Empty CSV fields mean "MiN stock config value".** qz's `MinTaskLearner` loads
   the MiN repo's per-benchmark stem config as defaults and applies only the
   recorded `min_*` overrides (`_load_model_defaults`, min_learner.py). The stem
   configs and their `-dinov3vitb16` variants are identical on every fallback field
   (verified against main@646e207), so the fallback-file ambiguity (L/H-suffixed
   configs may not have existed at qz-sweep time) is immaterial. Fallback values
   used: epochs=10, init_epochs=10 (omnibenchmark: 20), init_lr=0.001,
   buffer_size=16384, fit_epochs=3, weight_decay=init_weight_decay=5e-4,
   optimizer=sgd, scheduler=step.

3. **Protocol = EASE B0-IncN with seed-shuffled class order**, via the `_ease` base
   configs + the BigPurple repo's `--seed` override (seeds python/numpy/torch and
   shuffles class order the same way compcont-bench does). This matches how the
   published-config 120-run sweep and the dinov2 paperhp sweep were run. The qz
   winners themselves were found under qz's harness at seed 1993 with its own
   class-order shuffle; **MiN-repo seed 1993 and qz seed 1993 need not produce the
   identical class order**, so "roughly reproduce at 1993" is the right bar, not
   bit-equality.

4. **`buffer_batch` kept verbatim** even where it stresses memory
   (cifar-100/v3-H wants 96/1000 on an 840M backbone; the July sweep needed
   64/250 to fit H). It is a DataLoader batch size for the analytic fit
   (`fit_fc`/`re_fit`) — nominally accuracy-neutral, but it is recorded as a tuned
   value in the CSV, so it is not silently changed. `expandable_segments:True` is
   set; if a run OOMs after 3 attempts the fallback (reduce buffer_batch, rerun,
   record deviation here) will be applied explicitly, not silently.

5. **Runtime fits one 48h job.** Estimate ≈ 300 GPU·h (30 H-runs dominating) on
   8×H100 ≈ 38h wall. If the queue does not drain, a follow-up job is chained
   with `--dependency=afterany:<this job>` on sp-0014, same queue+claims dir
   (claims are persistent, so nothing re-runs).

6. **Results format**: same as all prior sweeps — compcont JSONs, seed-tagged
   (`MiN_<backbone>_seed<seed>.json`) under
   `min_dinov3_paperhp/results/paperhp/<benchmark>/`, written via
   `COMPCONT_RESULTS_DIR`. Success = `FINAL:` line in the log (exit codes are
   unreliable under enroot on sp nodes).
